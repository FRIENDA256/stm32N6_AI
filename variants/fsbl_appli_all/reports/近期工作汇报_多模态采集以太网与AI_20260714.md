## 一、本周工作目标

本周工作围绕统一工程 `fsbl_appli_all` 展开，重点解决以下问题：

1. 稳定 PoE 以太网链路，确认 AD7606、红外摄像头和可见光摄像头并行运行时不会明显破坏网络通信。

## 二、本周完成内容

### 2.1 以太网链路稳定与吞吐优化

完成了以太网地址网段调整和链路验证：

| 项目 | 当前配置 |
| --- | --- |
| STM32N6 IP | `192.168.6.50` |
| PC IP | `192.168.6.10` |
| 子网掩码 | `255.255.255.0` |
| TCP 命令端口 | `5000` |
| UDP echo 端口 | `5005` |
| PHY | RTL8211F |
| 链路状态 | `1000M-FD` |

早期测试中出现过 Ping 丢包、TCP 接收超时和吞吐量明显下降。例如 TCP 在接收约 2 MiB 数据后超时，Ping 丢包率曾达到 25%～50%。通过检查 PHY、ETH 时钟、ThreadX/NetX 线程优先级、AD7606 DMA 优先级和发送路径后，链路恢复稳定。

当前稳定测试结果如下：

| 测试场景 | TCP | UDP | 结果 |
| --- | ---: | ---: | --- |
| AD7606 后台运行，`--no-fill` | 约 `203.7 Mbps` | 约 `253.1 Mbps` | 32 MiB TCP 完整接收，UDP 无缺包 |
| 摄像头连续运行，`--no-fill` | 约 `203.7 Mbps` | 约 `252.6 Mbps` | 摄像头运行期间吞吐基本保持 |
| Pattern 填充 | 约 `159～161 Mbps` | 约 `200 Mbps` | 主要用于 CPU 和内存访问压力参考 |

一次稳定测试的关键输出为：

```text
TCP received: 33554432 bytes in 1.322s, 203.07 Mbps
TCP board rate: 203.67 Mbps

UDP received: 157849920 bytes, packets=107235, gaps=0, bad_magic=0
UDP board rate: 252.56 Mbps
UDP receive ratio: 100.0%
UDP trailing/missing packets: 0
```

当前结论是：以太网已经可以作为三类传感器数据和 AI 结果的统一上行接口，但上述吞吐量属于测试程序下的稳定基线，不等同于最终多路原始数据长期满负载发送能力。

### 2.2 AD7606 采集链路和并行运行验证

AD7606 继续使用 SPI4 + GPDMA + EXTI 方案：

| 功能 | STM32N6 资源 |
| --- | --- |
| SPI | SPI4 |
| TX DMA | GPDMA1 Channel 10 |
| RX DMA | GPDMA1 Channel 11 |
| 数据就绪中断 | EXTI |
| 采样帧 | 512 点、8 通道、16 bit |

通过 `ADGET` 获取到的稳定数据包含：

```text
SOURCE=AD7606 TYPE=0x01
TOTAL=8240 PAYLOAD=8212
CRC OK
points=512 channels=8 bytes_per_sample=2
CH4 min=6862 max=6868 avg=6865
```

本周对 AD7606 数据通路做了两项面向 AI 和并行运行的改进：

- 增加“最新完整帧”的安全复制接口，避免 AI 线程直接读取正在更新的 DMA 缓冲。
- 为最新帧缓存增加 seqlock 和内存屏障，降低帧信息、payload 和序号不一致的风险。

在最终稳定测试中，AD7606 的 CRC、帧序号和采样数据均正常。`STAT` 查询结果显示：

```text
pool_total=0x00000028
pool_free=0x00000020
pool_empty=0x00000000
```

说明当前以太网压力测试后，NetX packet pool 没有出现耗尽。

### 2.3 Tiny1C 红外链路和可见光摄像头调试

红外数据链路已经可以通过 TCP 命令独立获取：

```text
ADGET
IRGETIMG
IRGETTEMP
CAMSTAT
CAMGET
```

已验证内容包括：

- AD7606 原始波形帧；
- Tiny1C 红外图像帧；
- Tiny1C 温度帧；
- IMX219 RGB565 可见光图像帧；
- TCP 二进制帧头、payload 长度和 CRC32 校验。

IMX219 当前配置为 `640×480 RGB565`，单帧大小为：

```text
640 × 480 × 2 = 614400 bytes
```

在摄像头并行运行测试中，`CAMSTAT` 能够看到：

```text
size=640x480
stream=1
perr=0
cerr=0
derr=0x00000000
```

为降低系统压力，摄像头时序已经从约 50 fps 降到约 24 fps。降帧后的验证结果：

```text
CAMSTAT frame=6
10 秒后 CAMSTAT frame=246
```

即 10 秒增加约 240 帧，约为 24 fps。此时连续 `CAMGET` 获取 RGB565 图像可以通过 CRC 校验，且 AD7606 `ADGET` 仍能正常获取。

调试过程中曾在摄像头启动和 AD7606 并行时观察到一次 SPI4 DMA 错误和错误包头。随后通过降低摄像头帧率、调整优先级和减少周期性串口报告，最终测试恢复稳定。当前版本仍保留低频质量统计，便于后续长时间测试。

### 2.4 多模态系统架构规划

结合板卡上已有的 APS512XXN-OBR-BG PSRAM 和 MX66UW1G45GXDI00 OctaFlash，完成了多模态系统架构规划文档：

[MULTIMODAL_ARCHITECTURE_PLAN_20260710.md](../MULTIMODAL_ARCHITECTURE_PLAN_20260710.md)

规划中的数据路径为：

```text
AD7606 / SPI4 DMA
Tiny1C / SPI3 DMA
IMX219 / DCMIPP
        |
        v
独立 payload 缓冲池和 Frame Manager
        |
        +--> AI Scheduler --> NPU AI Worker --> AI Result Queue
        |
        +--> Network Scheduler
                 +--> Control TCP
                 +--> Reliable Data
                 +--> Media UDP
```

规划确定了以下原则：

- 每类传感器使用独立缓冲池和队列。
- DMA 当前使用的缓冲不能被网络或 AI 直接读取。
- 控制命令、状态和 AI 结果需要保留独立的网络资源。
- APS512 PSRAM 用于后续大 payload 和环形缓存。
- MX66 OctaFlash 用于固件、NPU 模型、配置和日志。
- AI 只能读取已经完成、具有明确序号和时间范围的数据。

当前 PSRAM 尚未正式作为运行时多缓冲区启用，仍需单独完成器件容量、RIF、Cache、CPU/HPDMA 并发访问和数据一致性验证。

### 2.5 NPU AI 第一阶段接入

本周开始将已有的 `tiny_temporal_mixer_8ch_int8` 模型接入 `fsbl_appli_all`。当前实现定位为“AD7606 单模态 AI 垂直切片”，用于先验证采集数据进入 NPU 的完整链路，不代表最终三模态融合模型。

当前 AI 配置：

| 项目 | 配置 |
| --- | --- |
| 模型 | `tiny_temporal_mixer_8ch_int8` |
| 输入 | 8 通道 × 1024 点 INT8 |
| 输入大小 | 8192 bytes |
| 输出 | 4 bytes INT8 |
| 权重地址 | `0x71000000` |
| 权重文件大小 | 98833 bytes |
| Activation 区 | `0x342E0000` 起始，约 344 KiB |
| AI 线程优先级 | 15 |
| AD7606 线程优先级 | 14 |

已加入的代码功能：

- `app_ai.c` / `app_ai.h` AI worker；
- AD7606 最新完整帧复制接口；
- 8 通道历史窗口维护；
- NPU RAM、RIF、RISAF、NPU cache 和中断配置；
- 模型权重指纹校验；
- AD 帧跳号时自动清空历史窗口；
- `AISTAT` TCP 状态命令；
- 推理次数、跳帧次数、窗口重置次数、推理错误和最近推理耗时统计。

当前串口预期输出：

```text
AI thread created
AI thread start
AI ready model=tiny_temporal_mixer_8ch_int8 source=AD7606
```

当前 AI 状态命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\tcp_ir.ps1 -Command AISTAT -TimeoutMs 60000
```

状态中 `weights=1` 表示权重探针校验通过，`runs` 表示已完成推理次数，`resets` 表示 AD 序号断档后重置历史窗口的次数。

需要明确的是，当前 AD 数据到 INT8 的 `s16_shift8` 只是临时预处理方式。后续必须根据 AD7606 量程、零点、通道标定数据和训练数据重新确定量化比例。

## 四、当前问题和边界

### 已解决或基本稳定的问题

- 以太网 Ping 丢包和 TCP 接收超时；
- AD7606 与 NetX 并行时的明显吞吐下降；
- 摄像头帧率过高导致的系统压力；
- AD7606 最新帧被并发读取时的数据一致性风险；
- NPU 模型权重和 activation 区的基本地址配置。

### 尚未完成的问题

1. AI 最新代码尚未完成板上烧录后的实测，仍需由板卡启动配置和烧录流程完成最终验证。
2. 当前 AI 只使用 AD7606，红外和可见光尚未进入同一个融合模型。
3. APS512 PSRAM 尚未承担 IMX219 多帧缓存和多路 payload 环形缓存。
4. Frame Manager、缓冲租约和多 worker 网络发布器还没有全部实现。
5. 当前可见光图像仍以 RGB565 原始帧为主，后续应评估 VENC 编码码流。
6. AI 预处理仍是临时 `s16_shift8`，需要结合标定和训练重新校准。
7. Ethernet baseline 检查脚本中仍有几项旧规则，与当前已验证的 98 KiB NetX 内存池和千兆配置不一致，需要后续同步维护。



## 五、阶段性结论

截至 2026 年 7 月 14 日，`fsbl_appli_all` 已经从“以太网、AD7606、红外和可见光功能分别验证”推进到“统一工程中并行运行和 AI 垂直切片接入”阶段。

当前最重要的实测结果是：在 `192.168.6.50` 网络配置下，AD7606 后台采集和 IMX219 约 24 fps 连续运行时，以太网仍可达到约 `203 Mbps TCP` 和 `252 Mbps UDP`，UDP 测试无缺包；摄像头图像和 AD7606 数据也可以分别通过 TCP 获取并完成 CRC 校验。
